# Stratum Visualizer — requirements & wishlist

Живой документ: *что должно быть и почему*. Как это сделано — в коде `frontend/stratum-visualizer-frontend/src/`.

## Цель

Визуализатор — это интерактивная карта зависимостей кодовой базы, на которой видно:

1. **Структуру** — слои, контейнеры (слайсы, sub-units, вложенные), модули, рёбра между ними.
2. **Состояние** — где нарушены правила Stratum: какие модули и рёбра ломают архитектуру.
3. **Динамику** — как нарушения появляются/исчезают между ревизиями: вид Merge request против `--base REF`.

Пользователь визуализатора — разработчик команды, который хочет за минуту понять «куда я попал?» в незнакомой части кода, и архитектор, который хочет за минуту понять «насколько мы отъехали от заявленной архитектуры?».

Не цель: заменить редактор, реплицировать UI VS Code, рендерить полную AST, давать quick-fix. Stratum — линтер, не рефакторер.

## Архитектурный контракт

- **Источник данных** — `GraphSnapshot v3` (`EngineInput::snapshot` в `stratum-engine`, графовые факты из `stratum_graph::snapshot_of`): `version: 3`, `project` (имя папки ROOT), `modules [{ id, path, container, layer, purity, zone?, territory }]`, `containers [{ id, name, path, kind, layer, parent, stage, entry }]`, `layers [{ id, name, depends_on }]`, `edges [{ from, to, kind }]`, `zones [{ id, path, root }]`, `territories [{ may_import_layers, imported_by_layers, max_import_purity, visible_zones, may_not: [{ rule, region }] }]`. Все пути — от ROOT через `/`, абсолютных путей машины в снапшоте нет. `purity` — ранг модуля 1–4, `stage` — стадия эволюции контейнера 1–4, `kind` — `layer | slice | sub_unit | nested`. `zone` — индекс в `zones` (приватная зона, в которой лежит модуль; нет поля — модуль не в зоне). `territory` — индекс в `territories`: одинаковые **Territory** хранятся один раз. `rule` — slug, `region` — `{ kind: 'siblings', parent, containerKind, containers }` или `{ kind: 'internals' }`. Фронт принимает ровно версию 3; при другой показывает экран «Visualizer out of date». Bump = координированный фронт-релиз (см. `RELEASE.md`). Типы фронта — `src/types.ts`; фикстура `tests/fixtures/tiny-ts-snapshot.json` генерируется тестом `stratum-lint` (`INSTA_UPDATE=always cargo test -p stratum-lint --test e2e_snapshot`).
- **Транспорт** — HTTP-сервер встроен в `stratum-lint`: `stratum-lint visualize [ROOT] [--config PATH] [--base REF] [--feature ID]... [--no-open]`, Axum + `rust-embed` для бандла, `127.0.0.1` на случайном порту. `/api/snapshot` — снапшот, `/api/violations` — нарушения (`rule` — slug, `file` — путь от ROOT, `modules`, `edge`), `/api/context?path=REL` — `text/plain`, байт в байт `stratum-lint context REL --format agent` (REL — путь от ROOT, файл может ещё не существовать; путь вне ROOT — 400), `/api/drift` — **Drift** против `--base REF`: `{ base: { ref, sha }, markdown, breaking, edges, layer_edges, slice_edges, cycles, stages, fan_in }`, где `markdown` — ровно отчёт `stratum-lint diff --base REF`, `breaking` — индексы в `edges` импортов, нарушающих правила, в порядке отчёта; без `--base` — 404, и вкладки Merge request нет. `/api/edge?from=&to=` (id модулей снапшота) или `?from_container=&to_container=` (id контейнеров как юнитов: модули контейнера и вложенных в него `nested`, без модулей слайсов и под-юнитов внутри него, у которых свой юнит) — контракт ребра: `{ imports: [{ file, line, type_only, kind, names: [{ name, type_only, decl }] }] }`, импорты по `file` и `line`; каждое имя пройдено через re-export и `export *` до объявления, `decl` — `{ path, line }` или `null` (пакет, нет имени, цикл), namespace-импорт — имя `*` со строкой 1 модуля; ребра нет — `{ imports: [] }`, без пары параметров — 400. `/api/source?path=REL&line=N&context=K` — `{ path, start, lines, total }`, строки `N−K..N+K` (K по умолчанию 20, максимум 200), без `line` — файл целиком, до 2000 строк; путь с `..`, абсолютный или вне ROOT — 400, нет файла — 404. `path=ID:REL` — файл под `root` системы `ID` из `systems` конфига (REL — путь от этого `root`, те же проверки на выход за него), `path` в ответе — тоже `ID:REL`; префикс, который не id системы с `root`, — часть обычного пути от ROOT. `/api/systems` — `{ systems: [{ id, name, self, contracts_total, unavailable? }], channels: [{ from, to, contracts: [{ id, signature, decl, callers: [{ module, line, owner, features }] }], unattributed }] }`: системы в порядке конфига, `contracts_total` — все объявленные контракты системы, вызванные или нет; `unavailable` — причина, по которой контракты не прочитаны (`root` не существует), прогон при этом не падает. Канал — от системы `self` к каждой системе, у которой есть вызванный контракт или неатрибутированный вызов; `contracts` — только вызванные, по `id`; `decl` — `{ path: "ID:REL", line }` или `null` (вызов называет контракт, которого нет в `root`; тогда и `signature` — `null`); `callers` — id модуля снапшота, строка вызова и `owner` — имя top-level объявления, внутри которого вызов (`null` на верхнем уровне), и `features` — id фич, которые выполняют вызов, по возрастанию. Фича выполняет вызов, если модуль вызова — её вход; если вызов на верхнем уровне модуля из её `modules`; или если другой модуль фичи импортирует имя, которое через re-export и `export *` ведёт к объявлению `owner` (`export default function foo` — к `foo`). Namespace-импорт, `export * as ns` и `require("…")` модуля выполняют все его объявления; `export … from` баррель-модуля передаёт имена дальше только тогда, когда сам баррель выполняется целиком (вход, namespace-импорт), поэтому `import { getUser } from "shared/api"` даёт фиче только вызовы внутри `getUser`. Type-only импорты и `import()` не выполняют ничего. Выполненное объявление выполняет и все top-level объявления своего модуля, на которые оно ссылается по имени, транзитивно (helper рядом с `getUser`; фабрика `createOrdersApi`, результат которой экспортирован как `ordersApi = createOrdersApi(…)`): ссылка — любой идентификатор в коде объявления, кроме позиций типов, локальная переменная с тем же именем тоже считается. Функция из другого модуля, которую вызывает выполненное объявление, отдельно не прослеживается: импорты модуля фичи считаются всегда, выполняется импортирующий код или нет. `stratum-lint c4 --feature` считает контракты по тому же правилу; `unattributed` — вызовы, совпавшие с `calls`, но без имени контракта (не строковый литерал, клиент фабрики ушёл в другой модуль). Без `systems` — 404. `/api/features` — `{ features: [{ id, name, entry, modules }], shared, selected }`: фичи из `features` конфига, без него — по одной на папку или файл прямо в первом слое с `slices: true`, включая папку, которую забрал вложенный слой; `entry`, `modules` и `shared` — id модулей снапшота по возрастанию, `modules` — входы и всё, что из них достижимо статическими импортами (type-only и `require("…")` тоже, `import()` и `import.meta.glob()` — нет), `shared` — модули двух и более фич, `selected` — id из `--feature` в порядке флагов, без флага `[]`; неизвестный id — exit 2 со списком известных. Те же множества путями печатает `stratum-lint features`. Остальное — статика фронта. Снапшот, нарушения, находки для `/api/context`, фичи, системы и Drift считаются один раз при старте, `/api/edge` и `/api/source` — на каждый запрос; неизвестный REF — exit 2 с подсказкой `git fetch`, как у `diff`. Адрес печатается в stderr (`stratum-visualizer ready at <url>`); `--no-open` не открывает браузер (для скриптов и агентов). `Ctrl+C` останавливает сервер.
- **Рендер** — SolidJS + SVG. Общий холст `src/canvas/` (пан, зум колесом, fit, экспорт SVG), модель графа `src/render/model.ts` (юниты, агрегированные рёбра, SCC, находки по модулям и рёбрам), у каждого вида своя раскладка в `src/views/<id>/`.
- **Конфиг** — `visualize` читает `ROOT/stratum.config.jsonc` или `--config`, fallback на zero-config. Тот же путь, что у `lint`; невалидный конфиг — exit 2.
- **Без сервера-снаружи** — всё через локальный binary, нет аккаунтов, телеметрии, облака. Открыто в браузере = всё.

## Перформанс-бюджет

| Метрика | Бюджет | Текущее (на 2026-10-16) |
|---|---|---|
| Первая отрисовка вида | ≤ 100 ms (в отчёт стенда) | ≤ 30.7 ms на большом реальном проекте |
| Отрисованных меток на сцене | ≤ 1 500 | ≤ 1 483 на большом реальном проекте |
| p95 обновления при пане/зуме | ≤ 16,7 ms | ≤ 7.5 ms на большом реальном проекте |
| Bundle (без sourcemaps) | < 1.5 MB | 511 KB на 2026-10-29 (с уровнем System и перетаскиванием блоков карты), из них ленивый chunk подсветки 33 KB |
| Cold lint feeding `visualize` | < 5 s на ~3K файлов | ≈ 0.36 s холодный (≈ 0.18 s с тёплым кэшем) на реальном проекте в ~4K модулей |

Первые три строки меряет **Bench** (`9`) на большом реальном проекте, см. ниже.

## Test target — большой реальный проект

Визуализатор проверяют на большом реальном проекте (~4K модулей, ~14K рёбер, закрытый). На нём ловятся проблемы, которых нет на tiny-ts: широкие графы, циклы, перформанс отрисовки. Репозитория проекта здесь нет, цифры в таблице выше сняты на нём.

Проверка после существенной правки рендера или раскладки:

1. `stratum-lint visualize <project> --base <REF> --no-open` — стартует, снапшот грузится без ошибки версии, есть вкладка Merge request.
2. Вид **Bench** (`9`), кнопка «Run bench» — стенд проходит все пороги.

Tiny-ts (`tests/fixtures/tiny-ts`) остаётся unit/CI-фикстурой.

## Что есть

- [x] Сервер `stratum-lint visualize [ROOT]` — случайный порт, открывает браузер (`open` crate), `--no-open` без браузера, `--config`, `--base REF`.
- [x] **Статический сайт** `stratum-lint export [ROOT] --out DIR [--with-source] [--base REF]` — тот же фронтенд и ответы всех `/api/*` файлами в `DIR/data/`; любой файловый сервер (GitLab Pages, GitHub Pages, `npx http-server`) показывает все виды, фильтр фич, Architecture с уровнем System, Contract и Code, с `--base` — Merge request. Нет только Brief файлов, которых ещё нет. Фронтенд узнаёт статический режим по `window.__STRATUM_STATIC__` в `index.html` (какие файлы выгружены: `source`, `systems`, `drift`); переключение — только в `src/lib/api.ts`. Пути ассетов относительные, сайт работает из подпапки. Связки контейнеров собираются на фронтенде из рёбер модулей (`edges.json`) и составов контейнеров (`members.json`). Исходники — только с `--with-source` (каждый модуль и объявления контрактов других систем); без него Code показывает `file:line` и сигнатуру, текста нет, и ничего кроме путей, имён и сигнатур из репозитория не выходит. Раскладка `data/` — [harness.md](harness.md), CI — [ci.md](ci.md#the-visualizer-on-pages).
- [x] `/api/snapshot` отдаёт `GraphSnapshot` v3, `/api/violations` — нарушения по тому же конфигу, что у `lint`, `/api/context` — **Brief** файла, `/api/drift` — **Drift**.
- [x] Виды (вкладки в шапке, клавиши, палитра; реестр — `src/views/index.ts`). У каждого вида своя левая панель (outline) и правая (детали выделения).
  - `1` **Module focus** — модуль с импортёрами и импортами по колонкам слоёв (`h` — второй хоп) или полосами (Bands), лента **Territory**: что модулю можно и нельзя импортировать. В деталях — **Brief** файла, экспорт SVG и «Add to set» (модуль уходит в Module set).
  - `2` **Matrix** — DSM слоёв или юнитов, разбиение на блоки циклов (SCC), клетки против `depends_on`. В деталях клетки — «Show in map»: Container map с выделенной парой (юниты — Blocks + bundles, слои — Layer graph).
  - `3` **Merge request** — только с `--base REF`: регион изменённых рёбер (добавленные, удалённые, файлы, которых нет в head) или карточка комментария (≤ 800×600, экспорт SVG) с markdown `stratum-lint diff` для копирования.
  - `4` **Container map** — вся архитектура на уровне юнитов (слайс или слой без слайсов), два варианта:
    - **Blocks + bundles** — блок на слой с юнитами внутри (высота ∝ √модулей, ширина — по имени, sub-units пунктиром, точка — есть ошибки), импорты между юнитами — связки (толщина ∝ log числа импортов, цвет severity — нарушение между слоями или в соседний слайс). Блоки идут по глубине `depends_on`: сначала слои, которые зависят от самой длинной цепочки, последним — слой без зависимостей; маленькие блоки встают рядом и друг под другом, всё вместе упаковано в прямоугольник ≈ 3:2, чтобы fit показал граф целиком с читаемыми подписями. Гейт рёбер: `rule breaks` (по умолчанию), `≥ 12 imports`, `all N`. Наведение или клик показывают рёбра одного юнита, двойной клик раскрывает юнит в сетку модулей и сворачивает обратно (раскрытые юниты хранятся в навигации). Юнит перетаскивается мышью куда угодно, слой целиком — за заголовок блока; рамка слоя тянется за своими юнитами, связки идут следом. Перетаскивание не выделяет, клик без движения выделяет, фон по-прежнему панорамирует. Сдвинутые позиции хранятся в `localStorage` на проект и вид (`stratum.positions:<project>:<view>`, по пути юнита) и переживают перезагрузку; «Reset layout» в правом верхнем углу возвращает раскладку.
    - **Layer graph** — слои колонкой, слева дуги, заявленные в `depends_on`, справа — незаявленные, с числом импортов и пар юнитов и слагами правил находок.
    - Детали: без выделения — число рёбер юнитов, рёбер с нарушениями, наибольший цикл юнитов, горячие точки по fan-in и ошибкам, список рёбер с нарушениями; юнит — входящие и исходящие юниты, находки, «Expand modules», «Focus entry» (Module focus на entry), «Find in matrix»; связка — импорты модулей (клик — Module focus). Outline — юниты по слоям с фильтром по подстроке пути.
  - `5` **Module set** — набор модулей и всё, что их связывает. Набор собирается из «Add to set» в Module focus, из циклов модулей в outline (циклы больше 40 модулей — только счётчик со ссылкой на Matrix) и поиском модуля по пути в outline. Варианты:
    - **Ring** — модули набора по кругу, импорты изогнутыми рёбрами.
    - **Arc** — модули в линию, импорт назад (замыкающий петлю) дугой над линией.
    - **Set matrix** — матрица «строка импортирует столбец», циклы — пунктирные блоки.
    - Модули не из набора, лежащие на кратчайших соединяющих путях (≤ 4 импортов, до 24 таких модулей), рисуются вместе с набором; список этих путей — «Paths outside the set».
    - **Cut score** импорта — сколько модулей петли выйдут из наибольшего цикла, если его убрать. Лучший разрез помечен на сцене (`✂ cut frees k/n`), в деталях — кратчайшая петля через него и список кандидатов по score. Экспорт SVG, «Clear set», удаление модуля из набора.
  - `6` **Architecture** — уровни System → Containers → Components → Code, хлебные крошки над сценой (система › проект › контейнер › модуль, клик — подняться). Двойной клик или `Enter` на выделенном — вниз, `Backspace` — вверх (выделенным остаётся то, из чего вышли); Esc работает как везде. Уровень и путь хранятся в навигации, перезагрузка их сохраняет (панель Code после перезагрузки открывается кнопкой «Open code»). Без `systems` в конфиге (`/api/systems` отвечает 404) уровня System нет и вид начинается с Containers.
    - **System** — данные `/api/systems` (через `src/lib/api.ts`). Блок на систему: `self` выделен цветом (двойной клик или `Enter` — его Containers), система с недоступным `root` — приглушённая, пунктиром, «contracts unavailable» и причина. Стрелка `self` → система на канал, подпись — число контрактов в использовании. Клик по стрелке (или строке канала в деталях) — в деталях контракты канала: имя (rpc `Service.Method` или команда) с объявлением `system-id:path:line`, сигнатура, вызовы `file:line (owner)`; «N calls not attributed» — вызовы матчеров, контракт которых не назван (клиент, переданный между модулями). Клик по контракту открывает Code на объявлении и первом вызове, клик по вызову — на этом вызове (роль `Call`) и объявлении. С фильтром фич контракт учитывается, только если его вызывает выбранная фича: по `callers[].features` от сервера (по имени, с точностью до `owner`), а у сервера без этого поля — если модуль вызова есть в модели; стрелки, числа и списки считаются так же.
    - **Containers** — те же Blocks + bundles, что в Container map (общий код сцены, гейт рёбер и перетаскивание; позиции хранятся отдельно от карты), без раскрытия юнитов. Клик по связке — в деталях секция Contract и импорты модулей связки; без выделения в деталях список связок между слайсами (клик выделяет связку). Объявление имени, которое пересекает границу слайсов, открывается за 2 действия: связка → имя в Contract → Code. С `systems` другие системы стоят портами в свободном месте упаковки (после последнего блока), пунктирные стрелки идут к ним от контейнеров, модули которых вызывают их контракты (подпись — число контрактов); клик по стрелке — контракты из этого контейнера с вызовами, клик по порту — канал целиком.
    - **Components** — модули одного контейнера (юнит со вложенными), сгруппированные по сегменту (первой подпапке, файлы в корне — `(root)`), с импортами между ними. Клик по импорту — Contract этого импорта. Если сцена не укладывается в 1 500 меток, импорты модулей заменяются стрелками между сегментами с числом импортов плюс импорты выделенного модуля, затем пропадают подписи модулей.
    - **Code** — панель Code на файле модуля (строка 1); имя из Contract на любом уровне открывает Code на объявлении.
  - `9` **Bench** — стенд, см. ниже.

## UX-принципы

- **Тёмная тема** — большинство IDE тёмные, контраст лучше. Светлой темы нет.
- **Никаких блокирующих диалогов** — всё inline: левая outline-панель, правая панель деталей. Единственный модальный оверлей — палитра.
- **Клавиатура**: `1`–`6`, `9` — виды; в Architecture `Enter` — уровень ниже, `Backspace` — выше; `v` — вариант вида; `f` — fit; `/`, Ctrl+P, Ctrl+K — палитра; Esc закрывает палитру, затем панель Code, затем снимает выделение, затем возвращает к предыдущему состоянию навигации; Ctrl+[ / Ctrl+] — левая / правая панель.
- **Подсказки** на узлах и рёбрах — нативные SVG `<title>` с задержкой браузера; подсказка клетки Matrix появляется сразу.

## Известные ограничения

- **Hot-reload снапшота** не сделан (P1): snapshot и нарушения считаются один раз при старте, после правки кода надо перезапустить `stratum-lint visualize`.

## Не-цели (явно)

- **Edit-in-place** — визуализатор только смотрит, не правит. Кнопка «исправить нарушение» = открыть файл в редакторе, не делать правку из браузера.
- **Auto-layout оптимизация** через ML / прочую магию — раскладки видов (колонки, полосы, матрица, кольцо, дуги) покрывают MVP. Custom Sugiyama — крайний случай.
- **Замена graphviz / mermaid для ad-hoc диаграмм** — это инструмент для конкретно Stratum-снапшотов, не общий граф-вьюер.
- **Облачный SaaS** — всё локально. Если команда хочет share — `stratum-lint snapshot --out` + статический хостинг JSON.
