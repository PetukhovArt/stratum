# Stratum Visualizer — requirements & wishlist

A living document: *what must exist and why*. How it is built is in the code, `frontend/stratum-visualizer-frontend/src/`.

## Goal

The visualizer is an interactive dependency map of a codebase. It shows:

1. **Structure** — layers, containers (slices, sub-units, nested), modules, edges between them.
2. **State** — where Stratum rules are broken: which modules and edges violate the architecture.
3. **Dynamics** — how violations appear and disappear between revisions: the Merge request view against `--base REF`.

The visualizer's users are a team developer who wants to understand "where am I?" in an unfamiliar part of the code within a minute, and an architect who wants to understand "how far have we drifted from the declared architecture?" within a minute.

Not goals: replacing the editor, replicating the VS Code UI, rendering a full AST, offering quick-fix. Stratum is a linter, not a refactoring tool.

## Architectural contract

- **Data source** — `GraphSnapshot v3` (`EngineInput::snapshot` in `stratum-engine`, graph facts from `stratum_graph::snapshot_of`): `version: 3`, `project` (ROOT folder name), `modules [{ id, path, container, layer, purity, zone?, territory }]`, `containers [{ id, name, path, kind, layer, parent, stage, entry }]`, `layers [{ id, name, depends_on }]`, `edges [{ from, to, kind }]`, `zones [{ id, path, root }]`, `territories [{ may_import_layers, imported_by_layers, max_import_purity, visible_zones, may_not: [{ rule, region }] }]`. All paths are relative to ROOT with `/`; the snapshot has no absolute machine paths. `purity` is the module rank 1–4, `stage` is the container evolution stage 1–4, `kind` is `layer | slice | sub_unit | nested`. `zone` is an index into `zones` (the private zone the module lies in; no field means the module is not in a zone). `territory` is an index into `territories`: identical **Territories** are stored once. `rule` is a slug, `region` is `{ kind: 'siblings', parent, containerKind, containers }` or `{ kind: 'internals' }`. The frontend accepts exactly version 3; on any other it shows the "Visualizer out of date" screen. A bump is a coordinated frontend release (see `RELEASE.md`). Frontend types are in `src/types.ts`; the fixture `tests/fixtures/tiny-ts-snapshot.json` is generated by a `stratum-lint` test (`INSTA_UPDATE=always cargo test -p stratum-lint --test e2e_snapshot`).
- **Transport** — an HTTP server built into `stratum-lint`: `stratum-lint visualize [ROOT] [--config PATH] [--base REF] [--feature ID]... [--no-open]`, Axum + `rust-embed` for the bundle, `127.0.0.1` on a random port. `/api/snapshot` is the snapshot, `/api/violations` the violations (`rule` is a slug, `file` is a path from ROOT, `modules`, `edge`), `/api/context?path=REL` is `text/plain`, byte for byte `stratum-lint context REL --format agent` (REL is a path from ROOT, the file may not exist yet; a path outside ROOT gives 400), `/api/drift` is the **Drift** against `--base REF`: `{ base: { ref, sha }, markdown, breaking, edges, layer_edges, slice_edges, cycles, stages, fan_in }`, where `markdown` is exactly the `stratum-lint diff --base REF` report and `breaking` holds indices into the `edges` of imports that break rules, in report order; without `--base` it gives 404 and there is no Merge request tab. `/api/edge?from=&to=` (snapshot module ids) or `?from_container=&to_container=` (container ids taken as units: the container's modules and those of the `nested` containers inside it, without the modules of slices and sub-units inside it, which have a unit of their own) is the edge contract: `{ imports: [{ file, line, type_only, kind, names: [{ name, type_only, decl }] }] }`, imports ordered by `file` and `line`; each name is followed through re-exports and `export *` to its declaration, `decl` is `{ path, line }` or `null` (a package, no such name, a cycle), a namespace import is the name `*` with line 1 of the module; no edge gives `{ imports: [] }`, a missing parameter pair gives 400. `/api/source?path=REL&line=N&context=K` is `{ path, start, lines, total }`, lines `N−K..N+K` (K defaults to 20, at most 200), without `line` the whole file, up to 2000 lines; a path with `..`, an absolute one or one outside ROOT gives 400, a missing file gives 404. `path=ID:REL` is a file under the `root` of system `ID` from the config's `systems` (REL is a path from that `root`, with the same checks against leaving it), and `path` in the response is `ID:REL` too; a prefix that is not the id of a system with a `root` is part of an ordinary path from ROOT. `/api/systems` is `{ systems: [{ id, name, self, contracts_total, unavailable?, external, description? }], channels: [{ from, to, contracts: [{ id, signature, decl, callers: [{ module, line, owner, features }] }], unattributed, via: [{ module, features }] }], actors: [{ id, name, description? }], links: [{ from, to, label? }] }`: systems in config order, `contracts_total` counts every declared contract of the system, called or not; `unavailable` is the reason the contracts were not read (`root` does not exist), and the run does not fail on it. A channel goes from the `self` system to each system that has a called contract, an unattributed call or a `via` module; `via` holds the snapshot ids of the modules that match the system's `via` globs, ascending, each with the ids of the features that reach it; `actors` are the config's `actors` in order, and `links` are the declared `uses` of actors and systems, `from` an actor or system id, `to` a system id; a frontend that predates these fields reads them as empty or `false`; `contracts` holds only the called ones, by `id`; `decl` is `{ path: "ID:REL", line }` or `null` (the call names a contract that is not in `root`; then `signature` is `null` too); `callers` holds the snapshot module id, the call line, `owner` — the name of the top-level declaration the call is inside (`null` at the top level), and `features` — the ids of the features that execute the call, ascending. A feature executes a call if the call's module is one of its entries; if the call is at the top level of a module in its `modules`; or if another module of the feature imports a name that leads through re-exports and `export *` to the declaration `owner` (`export default function foo` leads to `foo`). A namespace import, `export * as ns` and `require("…")` of a module execute all its declarations; `export … from` in a barrel module passes names on only when the barrel itself is executed as a whole (an entry, a namespace import), so `import { getUser } from "shared/api"` gives the feature only the calls inside `getUser`. Type-only imports and `import()` execute nothing. An executed declaration also executes every top-level declaration of its module that it references by name, transitively (a helper next to `getUser`; the factory `createOrdersApi` whose result is exported as `ordersApi = createOrdersApi(…)`): a reference is any identifier in the declaration's code except type positions, and a local variable with the same name counts too. A function from another module that an executed declaration calls is not traced separately: the imports of a feature module always count, whether the importing code is executed or not. `stratum-lint c4 --feature` counts contracts by the same rule; `unattributed` holds the calls that matched `calls` but have no contract name (not a string literal, a factory client passed to another module). Without `systems` it gives 404. `/api/features` is `{ features: [{ id, name, entry, modules }], shared, selected }`: the features from the config's `features`, and without it one per folder or file directly in the first layer with `slices: true`, including a folder taken over by a nested layer; `entry`, `modules` and `shared` are snapshot module ids, ascending, `modules` are the entries and everything reachable from them by static imports (type-only and `require("…")` too, `import()` and `import.meta.glob()` not), `shared` are the modules of two or more features, `selected` are the ids from `--feature` in flag order, `[]` without the flag; an unknown id is exit 2 with the list of known ones. `stratum-lint features` prints the same sets as paths. Everything else is frontend static files. The snapshot, violations, findings for `/api/context`, features, systems and the Drift are computed once at start, `/api/edge` and `/api/source` on every request; an unknown REF is exit 2 with a `git fetch` hint, as in `diff`. The address is printed to stderr (`stratum-visualizer ready at <url>`); `--no-open` does not open the browser (for scripts and agents). `Ctrl+C` stops the server.
- **Render** — SolidJS + SVG. A shared canvas `src/canvas/` (pan, wheel zoom, fit, SVG export), the graph model `src/render/model.ts` (units, aggregated edges, SCC, findings per module and edge), and each view has its own layout in `src/views/<id>/`.
- **Config** — `visualize` reads `ROOT/stratum.config.jsonc` or `--config`, with a zero-config fallback. The same path as `lint`; an invalid config is exit 2.
- **No external server** — everything goes through the local binary, no accounts, telemetry or cloud. Open in the browser = everything.

## Performance budget

| Metric | Budget | Current (as of 2026-10-16) |
|---|---|---|
| First view render | ≤ 100 ms (in the bench report) | ≤ 30.7 ms on a large real project |
| Labels drawn on a scene | ≤ 1 500 | ≤ 1 483 on a large real project |
| p95 update on pan/zoom | ≤ 16.7 ms | ≤ 7.5 ms on a large real project |
| Bundle (without sourcemaps) | < 1.5 MB | 568 KB as of 2026-11-04, of which the lazy highlighting chunk is 33 KB |
| Cold lint feeding `visualize` | < 5 s on ~3K files | ≈ 0.36 s cold (≈ 0.18 s with a warm cache) on a real project of ~4K modules |

The first three rows are measured by **Bench** (`9`) on a large real project, see below.

## Test target — a large real project

The visualizer is checked on a large real project (~4K modules, ~14K edges, closed source). It catches problems tiny-ts does not have: wide graphs, cycles, render performance. The project's repository is not here; the figures in the table above were taken on it.

Check after a significant render or layout change:

1. `stratum-lint visualize <project> --base <REF> --no-open` — starts, the snapshot loads without a version error, the Merge request tab is present.
2. The **Bench** view (`9`), the "Run bench" button — the bench passes all thresholds.

Tiny-ts (`tests/fixtures/tiny-ts`) stays the unit/CI fixture.

## What exists

- [x] Server `stratum-lint visualize [ROOT]` — random port, opens the browser (`open` crate), `--no-open` for no browser, `--config`, `--base REF`.
- [x] **Static site** `stratum-lint export [ROOT] --out DIR [--with-source] [--base REF]` — the same frontend, with the responses of every `/api/*` as files in `DIR/data/`; any file server (GitLab Pages, GitHub Pages, `npx http-server`) shows all views, the features filter, Architecture with the System, Contract and Code levels, and with `--base` the Merge request. Only the Brief of files that do not exist yet is missing. The frontend recognizes static mode by `window.__STRATUM_STATIC__` in `index.html` (which files were exported: `source`, `systems`, `drift`); the switch lives only in `src/lib/api.ts`. Asset paths are relative, so the site works from a subfolder. Container bundles are assembled on the frontend from module edges (`edges.json`) and container members (`members.json`). Sources only with `--with-source` (every module and the contract declarations of other systems); without it Code shows `file:line` and the signature, no text, and nothing but paths, names and signatures leaves the repository. The `data/` layout is in [harness.md](harness.md), CI in [ci.md](ci.md#the-visualizer-on-pages).
- [x] `/api/snapshot` serves `GraphSnapshot` v3, `/api/violations` the violations from the same config as `lint`, `/api/context` the file **Brief**, `/api/drift` the **Drift**.
- [x] Views (tabs in the header, keys, palette; registry in `src/views/index.ts`). Each view has its own left panel (outline) and right panel (selection details).
  - `1` **Module focus** — a module with its importers and imports by layer columns (`h` — second hop) or by bands (Bands), the **Territory** strip: what the module may and may not import. Details hold the file **Brief**, SVG export and "Add to set" (the module goes to Module set).
  - `2` **Matrix** — a DSM of layers or units, split into cycle blocks (SCC), cells against `depends_on`.
  - `3` **Merge request** — only with `--base REF`: a region of changes or a comment card (≤ 800×600, SVG export) with the `stratum-lint diff` markdown to copy. The region with no selection shows folders, not modules: each folder with changed imports (or that is their target, or that changed stage) is one box in its layer's lane; the box carries the folder path from the layer, `+a −r` for all changed imports out of it, a severity-colored dot with the number of rule-breaking imports out of it, `sN → sM` on a stage change (with a bright border) and "N deleted" for files absent from head. Layer lanes follow the layer order and wrap into rows so the picture fits the canvas proportions; small lanes sit side by side. With no hover only rule-breaking imports, cycle edges and removed imports that broke a rule are drawn — each as its own arrow from folder to folder, labelled with the rule. Hovering a folder draws its changed imports with other folders: one right-angled arrow per folder pair labelled `+a −r` (thickness grows with the count, dashed means removals only; a label that has no room is not drawn), and the other folders are dimmed. Clicking a fold arrow dims the rest and lists its imports in the details. Clicking a folder opens it: the folder's modules in a grid inside a frame, each module with the `+a −r` of its changed imports, around it only the folders it has changes with, and its imports from module to module or to a folder box; in a folder with more than 16 changed imports, with no hover only rule breaks are drawn. On top are "← All folders" and the path. Hovering a module in the opened folder, or clicking it (or a file in the left list), draws its changed and unchanged imports (unchanged ones when the other end is on screen); clicking a change row on the right or a violation arrow opens the importing module's folder with that import; clicking a neighbouring folder's box opens it. A double click on a module or file (or "Open in Module focus" in the details) opens Module focus; Esc returns to all folders.
  - `5` **Module set** — a set of modules and everything that connects them. The set is built from "Add to set" in Module focus, from module cycles in the outline (cycles over 40 modules show only a count with a link to Matrix) and from a module path search in the outline. Variants:
    - **Ring** — the set's modules in a circle, imports as curved edges.
    - **Arc** — modules in a line, a back import (closing a loop) as an arc above the line.
    - **Set matrix** — a "row imports column" matrix, cycles as dashed blocks.
    - Modules outside the set that lie on the shortest connecting paths (≤ 4 imports, up to 24 such modules) are drawn with the set; the list of these paths is "Paths outside the set".
    - The **Cut score** of an import is how many modules of the loop leave the largest cycle if it is removed. The best cut is marked on the scene (`✂ cut frees k/n`); the details hold the shortest loop through it and a list of candidates by score. SVG export, "Clear set", removing a module from the set.
  - `6` **Architecture** — the levels System → Containers → Components → Code, with breadcrumbs above the scene (system › project › container › module, a click goes up). A double click or `Enter` on the selection goes down, `Backspace` goes up (what you came out of stays selected); Esc works as everywhere. The level and path are kept in navigation, so a reload keeps them (after a reload the Code panel opens with the "Open code" button). Without `systems` in the config (`/api/systems` answers 404) there is no System level and the view starts at Containers.
    - **System** — data from `/api/systems` (through `src/lib/api.ts`), laid out in three zones (`src/views/arch/system-layout.ts`): Roles on top, a person box per `actors` entry with its description; System in the middle, `self` with the product's other systems left and right of it; External infrastructure below, the `external: true` systems with a dashed border and an "external" tag, each placed under the systems that point at it. A block per system: `self` is highlighted in color (a double click or `Enter` opens its Containers), a system with an unavailable `root` is dimmed, dashed, with "contracts unavailable" and the reason; every block shows its `description` under the name. An arrow `self` → system per channel, labelled with the number of contracts in use, "via N modules" for the modules matched by the system's `via` globs, or both; systems in one row are joined by a straight arrow. Declared `uses` of actors and systems are thin dotted arrows with their label, lighter than the measured channels; a declared `uses` from `self` to a system it also calls is not drawn twice, its label goes in front of the channel's numbers. Selecting a channel with `via` modules lists them in the details under "N modules reach it directly": a click opens the module in Code, a double click opens its Module focus; Containers lists the `via` modules of each block's port arrow the same way. Clicking the arrow (or a channel row in the details) shows the channel's contracts in the details: the name (rpc `Service.Method` or a command) with its declaration `system-id:path:line`, the signature, the calls `file:line (owner)`; "N calls not attributed" counts matcher calls whose contract is not named (a client passed between modules). Clicking a contract opens Code on the declaration and the first call, clicking a call opens it on that call (role `Call`) and the declaration. With the features filter a contract counts only if a chosen feature calls it: by `callers[].features` from the server (by name, down to `owner`), and with a server lacking that field, if the call's module is in the model; a `via` module counts by its `features` the same way; arrows, numbers and lists are counted the same way.
    - **Containers** — one scene of blocks and links (`src/views/arch/boxes-scene.tsx`, layout in `boxes-layout.ts`). A block per feature (the folder of its entries) and per top layer for units outside feature folders; without `/api/features` (and until it answers) a block per top layer. Blocks stand in rows by the `depends_on` rank of their layer (a Rows/Columns toggle), and the order and spacing in a row are chosen for the fewest crossings, bends and the shortest links. A link is the imports between two blocks: an orthogonal line with rounded corners and few turns along the corridors between rows, labelled with the import count, thickness ∝ log of the count, severity color for a rule violation (between layers, into a sibling slice, a cycle); links with a shared end run along a shared trunk. A **hub** is a block that links from many blocks enter; a link into a hub from a block two or more ranks higher that breaks no rule is drawn as a stub (hub stub) — a tag at the source with the hub's name and the import count, with no line across the whole scene. With no selection all violations and the 16 heaviest of the other links are drawn, the rest is "N weaker links hidden — click a block": clicking a block draws all its links as real lines. Clicking a link or a stub shows its Contract in the details (names by the unit bundles inside the link, up to 30 bundles) and the list of these bundles (a click shows the Contract and module imports of one bundle); for a link of one bundle, the module imports right away. The declaration of a name that crosses a block boundary opens in 2 actions: link → name in Contract → Code. A double click or `Enter` on a block opens its units (the same view, a block per unit), or Components if there is one unit. With no selection the details list the bundles between slices (a click selects the bundle). The layout is computed: blocks are not dragged, positions are not stored, and there is no "Reset layout" button and no edge gate (`rule breaks` / `≥ N imports` / `all`). Layer → layer links are in Matrix. With `systems`, the other systems stand as ports in a separate row, and dashed arrows go to them from the blocks whose units call their contracts (labelled with the number of contracts, visible on the selected block); clicking an arrow shows the contracts by the block's units with calls, clicking a port shows the whole channel. All lines of the Architecture scenes are drawn by one component, `src/render/edge.tsx` (a wide transparent path for clicks, severity color only on violations).
    - **Components** — the modules of one container (a unit with its nested ones), grouped by segment (the first subfolder; files at the root are `(root)`), with the imports between them. Clicking an import shows that import's Contract. If the scene does not fit into 1 500 labels, module imports are replaced by arrows between segments with the import count plus the imports of the selected module, and then module labels disappear.
    - **Code** — the Code panel on the module's file (line 1); a name from Contract at any level opens Code on the declaration.
  - `9` **Bench** — the bench, see below.
- [x] **Edge contract** — the "Contract" section in the details of the selected edge: a bundle in Module focus (a click on a bundle or a group pill), a block link and a unit bundle in Architecture at the Containers level (a click on a link, a hub stub or a bundle row in the details), an import in Module set (a click on an edge or a cut) and an import in Architecture at the Components level. The names that pass through the edge (the union over all imports of the bundle, `type` meaning type-only), each with its declaration `path:line` behind barrels or `unresolved`; below, the same names by importer `file:line`. Data comes from `/api/edge` (a module edge uses `from`/`to`, a unit bundle `from_container`/`to_container`; in Module focus up to 30 edges of the bundle), lazily on selection. All requests to these endpoints go through `src/lib/api.ts`: response parsing and a cache by URL; a failed request is not cached.
- [x] **Code** — a panel under the scene (not modal, the scene and details stay visible): clicking a name in Contract shows `/api/source` around the import (±4 lines) and around the declaration (±12 lines), with the relevant line highlighted. Highlighting is `highlight.js` core with TypeScript, Rust and Protobuf, a separate chunk loaded the first time Code opens; files of other types (`.vue`) show plain text. Esc or `×` closes the panel.
- [x] **Features filter** — in the header: the `FEATURES` button opens the list of features (name and module count), a click chooses or clears a feature; "Show all features" clears them all. An empty choice means no filter; the initial choice is `selected` from `/api/features` (`visualize --feature ID`) until the user chooses. All views show only the union of the chosen features: the model (`src/render/model.ts`) is built once per (snapshot, choice) from the union's modules, the edges between them, the containers they lie in (containers left empty disappear) and the findings on them; all layers stay. Merge request drops the changes that touch hidden modules; the card markdown stays the full `diff` report. A module used by two or more chosen features is marked **shared** (a teal outline or stripe, "shared by two or more chosen features" in the tooltip, `data-shared="true"`) in Module focus (rows and lane boxes), Module set, Merge request and Architecture (Components level). "hide common > k" (k defaults to 3) hides the modules used by more than k of all features, with no features chosen too. Without `/api/features` (404 or an error) there is no button, and everything else works.
- [x] `v` switches the view variant (Columns/Bands, layer/unit, region/card, Ring/Arc/Set matrix). The navigation state (view, focus, variants, set, Architecture level and path, features filter and hide common) is kept in `localStorage`; the selection is not.
- [x] **Palette** (Ctrl+K, Ctrl+P, `/`): views and modules by path substring, up to 60 rows; a module opens in Module focus.
- [x] Interface language `EN | RU` in the header, the choice kept in `localStorage`. Fonts (Inter Tight, JetBrains Mono, Latin and Cyrillic) are in the bundle, no network.
- [x] **Bench** (`9`): runs the canonical questions for Module focus, Matrix, Merge request, Module set and Architecture (where a name that one slice imports from another is declared: the probe clicks the block link on the scene that carries a bundle between slices and finds its Contract in the details (if such bundles lie inside one block, it clicks the bundle row in the details); which contracts of another system the container with the most of them calls: the probe clicks the arrow from that container's block to the port and finds its contracts with `file:line` calls; the answer is found in the DOM by `data-testid`, ≤ 3 actions) and render measurements (time, labels ≤ 1 500, pan/zoom p95 ≤ 16.7 ms, severity colors only on severity labels, rules on edges against the linter, MR card ≤ 800×600), and with `systems` the System level too. Without `/api/drift` the MR question is skipped, and without `/api/systems` the systems question, rather than failed. Started with the "Run bench" button on a live `visualize`.
- [x] Header counters: modules, edges, errors, warnings.
- [x] CI: bundle-size budget (without sourcemaps), unit + Playwright smoke.

## Wishlist (prioritized)

### P1 — raises value

- [ ] **Saving the viewport** (pan, zoom) in `localStorage` — so a reload does not reset it. Now only navigation is stored.
- [ ] **Layout-direction toggle** (LR ↔ TB) — TB is handy for presentations.
- [ ] **Live-reload** via `--watch`: on file changes, recompute the snapshot + violations and update the scene, including edits to `.rhai` plugins.

### P2 — desirable

- [x] **Diff mode** — the Merge request view on `stratum-lint visualize --base REF` (working tree against a git revision, no snapshot files).
- [ ] **Image export** of any view — for PR descriptions and presentations. Now only Module focus, Module set and the Merge request card export SVG; no PNG.
- [ ] **Shareable URL** — the navigation state is encoded in the hash; you copy the link and a colleague opens the same view and the same module. Works locally (same snapshot), needs no server.
- [ ] **Transition animation** on expand and focus.
- [ ] **Custom layer colors** — configured in `stratum.config.jsonc`, so the color scheme matches the team's design system.

### P3 — later / optional

- [ ] **Server-side layout for huge graphs** (> 5K modules). The view layouts are checked on a large real project (~4K modules).
- [x] **Aggregation** — Architecture at the Containers level shows units and bundles; a unit's modules are the Components level, on a double click.
- [ ] **Multi-snapshot** — open several projects in one tab, see dependencies between them (if they exist through workspace/monorepo links).
- [ ] **Voice-over / a11y** — keyboard navigation over the graph, a screen reader for the outline.

## UX principles

- **Dark theme** — most IDEs are dark, contrast is better. There is no light theme.
- **No blocking dialogs** — everything is inline: the left outline panel, the right details panel. The only modal overlay is the palette.
- **Keyboard**: `1`–`3`, `5`, `6`, `9` — views; in Architecture `Enter` — a level down, `Backspace` — up; `v` — view variant; `f` — fit; `/`, Ctrl+P, Ctrl+K — palette; Esc closes the palette, then the Code panel, then clears the selection, then returns to the previous navigation state; Ctrl+[ / Ctrl+] — left / right panel.
- **Tooltips** on nodes and edges are native SVG `<title>` with the browser's delay; the Matrix cell tooltip appears immediately.

## Known limitations

- **Snapshot hot-reload** is not done (P1): the snapshot and violations are computed once at start, after a code change `stratum-lint visualize` must be restarted.

## Non-goals (explicit)

- **Edit-in-place** — the visualizer only views, it does not edit. A "fix the violation" button = open the file in the editor, not make an edit from the browser.
- **Auto-layout optimization** through ML / other magic — the view layouts (columns, bands, matrix, ring, arcs) cover the MVP. A custom Sugiyama is a last resort.
- **Replacing graphviz / mermaid for ad-hoc diagrams** — this is a tool for Stratum snapshots specifically, not a general graph viewer.
- **Cloud SaaS** — everything is local. If a team wants to share — `stratum-lint snapshot --out` + static JSON hosting.
